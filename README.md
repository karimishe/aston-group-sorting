# aston-group-sorting

Учебное консольное приложение для сортировки автомобилей на Java. У автомобиля три поля: мощность, модель и год выпуска.

Сейчас работают загрузка из файла и сортировка вставками. Порядок сравнения: мощность, при равенстве — модель, затем год. В меню предусмотрены ручной ввод, генератор, другие алгоритмы и сравнение по отдельным полям. Пока эти варианты не подключены, они помечены «не реализовано».

## Запуск

Приложение использует стандартную библиотеку Java, тесты — JUnit 5. Сборка настроена через Maven. В репозитории есть Maven Wrapper: скрипты `mvnw` и `mvnw.cmd` скачивают и запускают нужную версию Maven. Устанавливать Maven отдельно не требуется; для первого запуска нужен интернет.

Нужен установленный JDK 8 или новее. Исходники совместимы с Java 8; сборка и тесты проверены на Oracle JDK 25.0.4.1. Отдельный запуск на JDK 8 не проверялся.

### IntelliJ IDEA

1. Откройте папку `aston-group-sorting` или файл `pom.xml` через **File → Open** и импортируйте проект как Maven.
2. В **Project Structure → Project** выберите установленный JDK.
3. Дождитесь загрузки зависимостей. IDEA определит папки `src` и `test` и уровень Java из `pom.xml`. Если проект уже был открыт, нажмите **Reload All Maven Projects** в окне Maven.
4. Запустите метод `main` в [Main.java](src/sorting/app/Main.java).

В конфигурации запуска **Working directory** должна указывать на корень проекта. Аргументы программы не нужны.

### Терминал

Из корня проекта на macOS или Linux:

```sh
./mvnw compile
java -cp target/classes sorting.app.Main
```

В Windows PowerShell:

```powershell
.\mvnw.cmd compile
java -cp target/classes sorting.app.Main
```

JDK 25 может вывести предупреждение об устаревшей целевой версии 8. Оно не мешает сборке.

## Примеры данных

Файлы в `examples` предназначены для загрузки через меню:

| Файл | Для чего нужен |
| --- | --- |
| [cars-valid.txt](examples/cars-valid.txt) | Три корректных автомобиля, в том числе модель на кириллице |
| [cars-sort.txt](examples/cars-sort.txt) | Шесть автомобилей: есть одинаковые мощности, модели и повторяющиеся записи для проверки сортировки |
| [cars-invalid.txt](examples/cars-invalid.txt) | Ошибка во второй строке: отрицательная мощность |

Формат — UTF-8 без заголовка, одна запись на строку:

```text
150;Kia;2020
```

Правила значений и загрузки описаны в [архитектуре](docs/architecture.md#формат-файла).

## Ручная проверка

Запустите `Main` и вводите по одной строке, нажимая Enter:

```text
1
1
examples/cars-sort.txt
6
3
2
1
1
4
0
```

Это загрузка из файла, просмотр исходных данных, выбор сортировки вставками и сравнения по трём полям, просмотр результата и выход. Первым в результате должен быть `100;Volvo;2022`, последним — `200;Audi;2010`. Две записи `150;Kia;2018` должны сохраниться. Команда `3` после сортировки показывает прежний исходный порядок.

Для проверки ошибок:

- Введите текст или номер вне диапазона меню — программа должна повторить запрос.
- Запросите семь записей из `cars-sort.txt` — файл содержит только шесть.
- Загрузите `cars-invalid.txt`, запросив одну запись — ошибка во второй строке всё равно должна отклонить файл, поскольку проверяются все строки.
- После ошибочной загрузки проверьте команды `3` и `4`: прежние данные и результат должны сохраниться.

Неготовые пункты возвращают в главное меню без изменения коллекций. `0` в подменю возвращает назад, `0` в главном меню завершает программу. Закрытие потока ввода до выбора выхода считается ошибкой ввода.

## Тесты

Все тесты запускаются одной командой из корня проекта. На macOS или Linux:

```sh
./mvnw clean test
```

В Windows PowerShell:

```powershell
.\mvnw.cmd clean test
```

Новые тесты пишем на JUnit 5: методы помечаем `@Test`, результат проверяем через `Assertions`, имена классов заканчиваем на `Test`. Пример — [CarAllFieldsComparatorTest](test/sorting/compare/CarAllFieldsComparatorTest.java). Maven найдёт такие тесты автоматически.

Существующие проверки с `main` подключены через [CoreRegressionTest](test/sorting/CoreRegressionTest.java): его JUnit-тесты вызывают эти методы. Поэтому общая команда выполняет и старые, и новые проверки. Каждый сохранённый `main` можно по-прежнему запустить отдельно.

В IDEA тесты запускаются кнопкой рядом с JUnit-классом или методом; весь набор — через Maven, цель `test`. Отчёты Maven сохраняются в `target/surefire-reports`. Файловые тесты создают временные файлы и удаляют их после выполнения.
