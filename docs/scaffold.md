# Каркас приложения

Каркас — общая часть приложения, к которой команда подключает отдельные реализации. На первом этапе он включал файловый источник, сравнение по трём полям и сортировку вставками. Сейчас через него работают все источники, алгоритмы и дополнительные функции проекта.

## Что относится к каркасу

| Часть | Ответственность |
| --- | --- |
| `Main` | Создать зависимости, запустить приложение, сообщить о технической ошибке ввода |
| `ConsoleApplication` | Показать меню, вызвать выбранный модуль, хранить исходную коллекцию и результат |
| `ConsoleInput` | Читать строки и числа из общего потока ввода, повторять запрос при неверном числе |
| `Modules` | Создать конкретные реализации источников, алгоритмов, компараторов и дополнительных модулей |
| Интерфейсы в `sorting.contract` | Задать общие методы и правила взаимодействия модулей |
| `Car` и `Car.Builder` | Представить автомобиль и проверить его поля при создании |
| `MyArrayList<T>` | Хранить элементы, предоставлять доступ по индексу и создавать копию контейнера |

Исходная коллекция и результат хранятся отдельно. Меню передаёт сортировке копию и сохраняет её только после успеха. Ошибка загрузки или сортировки оставляет прежние данные доступными; успешная загрузка новой коллекции сбрасывает старый результат.

## Где заканчивается каркас

Источник отвечает за получение и проверку данных, алгоритм — за перестановку элементов, компаратор — за сравнение двух объектов. Запись в файл, подсчёт совпадений и сортировка чётных значений также выполняются отдельными модулями. Меню выбирает операцию и показывает результат, а не реализует её алгоритм.

Источники получают общий `ConsoleInput` или другие настройки через конструктор. Конструктор не начинает диалог: чтение происходит при вызове `load(length)`. Количество элементов запрашивает меню. Правила работы и обработки ошибок описаны в [контрактах](contracts.md).

## Как подключать изменения

При замене реализации существующего модуля достаточно сохранить его контракт и изменить соответствующий метод в `Modules`. Для нового источника или алгоритма, которого ещё нет среди пунктов меню, потребуется также добавить его выбор в `ConsoleApplication`. Такие изменения согласуем с авторами соседних модулей.

В обычном `Modules` все предусмотренные реализации подключены. Пометка «не реализовано» используется при временном отключении вариантов, для которых меню поддерживает такую проверку.

Каждый автор добавляет тесты своей реализации и проверяет вызов через меню. Общие файлы меняем только в пределах задачи, без переоформления соседнего кода. Порядок работы с ветками и PR описан в [правилах команды](development-plan.md).
