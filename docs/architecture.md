# Архитектура

Приложение сортирует автомобили `Car` с тремя полями: мощность, модель и год выпуска. Сейчас работают загрузка из файла, сортировка вставками и просмотр исходной коллекции и результата. Ручной ввод, генератор и остальные алгоритмы команда добавит по [плану разработки](development-plan.md).

## Структура проекта

| Пакет в `src/sorting/` | Классы и назначение |
| --- | --- |
| `app` | `Main` запускает приложение; `ConsoleApplication` управляет меню и хранит коллекции; `Modules` создаёт подключённые источники, алгоритмы и компараторы |
| `input` | `ConsoleInput` читает строки и числа из консоли, повторяет запрос при неверном числе |
| `model` | Неизменяемый `Car` и вложенный `Car.Builder` для создания и проверки автомобиля |
| `collection` | `MyArrayList<T>` — коллекция с добавлением, доступом по индексу и копированием |
| `contract` | Интерфейсы источников, сортировок и дополнительных модулей |
| `source` | `FileCarSource` читает файл, `CarLineParser` преобразует одну строку в `Car` |
| `compare` | `CarAllFieldsComparator` задаёт порядок сравнения автомобилей |
| `algorithm` | `InsertionSort<T>` переставляет элементы с помощью переданного компаратора |

В `test/` находятся тесты, в `examples/` — файлы с автомобилями, в `docs/` — документация команды. Пакеты `source/stream`, `output` и `count` появятся при реализации дополнительных заданий.

## От ввода до результата

1. `Main` создаёт один `ConsoleInput`, `Modules` и меню.
2. Пользователь выбирает источник в подменю и вводит количество автомобилей. Для файла сначала указывает путь.
3. Меню получает источник через `Modules` и вызывает `load(length)`.
4. Файловый источник передаёт строки в `CarLineParser`. Парсер проверяет формат и создаёт автомобили через `Car.Builder`.
5. После успешной загрузки меню сохраняет полученную `MyArrayList<Car>` как исходную коллекцию.
6. Пользователь выбирает алгоритм, затем способ сравнения. Меню получает их через `Modules` и копирует исходную коллекцию.
7. Алгоритм сортирует копию. После успеха меню сохраняет её как результат, который можно вывести отдельной командой.

Главное меню работает в цикле. Пункт `0` завершает программу; в подменю он возвращает назад. Неверное число повторяет текущий запрос. Конец консольного ввода передаётся в `Main` как техническая ошибка, а не считается командой выхода.

Пока доступны файловый источник, сортировка вставками и сравнение по трём полям. После выбора доступного алгоритма, если данные загружены, открывается меню «Способ сравнения»: `1` — по трём полям, `2` — по мощности, `3` — по модели, `4` — по году, `0` — назад в главное меню.

Меню автоматически помечает неподключённые варианты «не реализовано». Выбор такого пункта или возврат через `0` не меняет данные и прежний результат.

## Модель и проверка данных

У `Car` три обязательных поля:

- `power` — положительное целое число;
- `model` — непустая строка после удаления пробелов по краям; `;` и переводы строк запрещены в любом месте исходного значения;
- `productionYear` — целое число от 1900 до текущего года включительно.

Эти ограничения проверяет `Car.Builder.build()`. Все источники должны создавать автомобили через Builder, чтобы правила не расходились. Парсер отвечает за формат строки и преобразование чисел, Builder — за допустимость значений.

### Формат файла

UTF-8, без заголовка, одна запись на строку:

```text
150;Kia;2020
100;Audi;2018
120;Лада;2022
```

Поля разделяются `;`, пробелы по краям удаляются. Полей должно быть ровно три. Пустая строка, неверное число или недопустимое значение отклоняют загрузку; сообщение содержит номер строки и причину.

`FileCarSource` проверяет **весь файл**, даже если запрошено меньше записей. После проверки возвращает первые `length` автомобилей. Если записей недостаточно, загрузка завершается ошибкой.

## Сортировка и сохранение данных

Компаратор сравнивает два объекта, алгоритм переставляет элементы коллекции. В `CarAllFieldsComparator` порядок фиксирован: мощность → модель → год. Следующее поле учитывается только при равенстве предыдущих. Числа сравниваются по возрастанию, модели — через `String.compareTo`, с учётом регистра.

```java
MyArrayList<Car> result = cars.copy();
strategy.sort(result, comparator);
```

Здесь `strategy` и `comparator` уже выбраны в меню. `copy()` создаёт отдельный контейнер с теми же ссылками на автомобили. Этого достаточно: `Car` не меняется после создания. Сортировка сохраняет размер коллекции и все повторяющиеся элементы.

Исходные данные и результат хранятся отдельно. Успешная загрузка заменяет исходную коллекцию и сбрасывает старый результат. Ошибка загрузки или сортировки оставляет прежние данные и результат доступными. Сам алгоритм при исключении может успеть изменить полученную коллекцию, поэтому меню передаёт ему копию и сохраняет результат только после успеха.

## Как расширять приложение

`SortStrategy<T>` — интерфейс алгоритмов, через который реализован паттерн Strategy: меню вызывает один метод `sort`, а порядок перестановок определяет выбранная реализация. Источники аналогично подключаются через `DataSource<T>`. Точные параметры и правила работы описаны в [контрактах модулей](contracts.md).

`T` — тип элементов. Коллекция и алгоритмы работают с ним, не обращаясь к полям `Car`. Для нового порядка нужен другой компаратор. Для другой модели также потребуются свои источники и проверка данных, но универсальные алгоритмы останутся прежними.

Команда добавит ручной и случайный источники, отдельные компараторы для каждого поля, сортировки выбором и пузырьком. Для каждого из них в `Modules` подготовлен метод создания объекта. Участник заменяет `return null` на создание своей реализации; доступность пункта меню меняется автоматически. Переписывать меню не требуется. Точные методы подключения перечислены в [контрактах](contracts.md#подключение).

Общий `ConsoleInput` уже готов; `CarConsoleReader` и `CarGenerator` будут написаны вместе с новыми источниками. Конструкторы модулей не читают данные: работа источника начинается в `load(length)`.

После основной части добавим сортировку только чётных значений мощности, запись в конец файла, заполнение через Stream и многопоточный подсчёт. Для них есть интерфейсы и [контракты](contracts.md); управление этими функциями через меню будет добавляться поэтапно.

Собственная коллекция обязательна только в дополнительном пункте `3*`; здесь уже используется `MyArrayList<T>`. Выбор `Car`, трёх алгоритмов и приоритета полей — решения команды. В [условии задания](requirements.md) конкретный приоритет и число алгоритмов не заданы. Состав минимальной рабочей версии описан в [каркасе проекта](scaffold.md).
