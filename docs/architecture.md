# Архитектура

Приложение сортирует автомобили `Car` с тремя полями: мощность, модель и год выпуска. Данные загружаются из файла, вводятся вручную или создаются генератором. Все три подключённых источника заполняют собственную коллекцию через Stream. Пользователь выбирает алгоритм и правило сравнения; отдельные операции сортируют чётные мощности, считают совпадения в нескольких потоках и дописывают результат сортировки в файл.

## Структура проекта

| Пакет в `src/sorting/` | Классы и назначение |
| --- | --- |
| `app` | `Main` запускает приложение; `ConsoleApplication` управляет меню и хранит исходную коллекцию и результат; `Modules` создаёт реализации модулей |
| `input` | `ConsoleInput` читает строки и числа, повторяет запрос при неверном числе |
| `model` | Неизменяемый `Car` и вложенный `Car.Builder` для создания и проверки автомобиля |
| `collection` | `MyArrayList<T>` хранит элементы, увеличивает внутренний массив и создаёт копию контейнера |
| `contract` | `DataSource`, `SortStrategy`, `EvenSorter`, `ResultWriter`, `OccurrenceCounter` задают методы взаимодействия модулей |
| `source` | `StreamFileCarSource`, `StreamManualCarSource`, `StreamRandomCarSource` заполняют коллекцию; `CarLineParser`, `CarConsoleReader`, `CarGenerator` создают автомобили; `CarCounter` считает совпадения |
| `compare` | `CarAllFieldsComparator`, `CarPowerComparator`, `CarModelComparator`, `CarProductionYearComparator` задают правила сравнения |
| `algorithm` | `InsertionSort<T>`, `SelectionSort<T>`, `BubbleSort<T>` сортируют коллекцию; `EvenValueSorter<T>` ограничивает сортировку элементами с чётным значением поля |
| `output` | `CarFileWriter` добавляет автомобили в конец файла |

В `test/` находятся тесты, в `examples/` — входные файлы с автомобилями, в `docs/` — документация команды. В пакете `source` также сохранены `FileCarSource`, `ManualCarSource` и `RandomCarSource`; меню использует реализации с префиксом `Stream`.

## От ввода до результата

1. `Main` создаёт общий `ConsoleInput`, объект `Modules` и меню.
2. Пользователь выбирает источник и количество автомобилей. Для файла сначала указывает путь.
3. Меню получает источник через `Modules` и вызывает `load(length)`.
4. Источник создаёт автомобили внутри последовательного Stream: разбирает строки через `CarLineParser`, читает поля через `CarConsoleReader` или вызывает `CarGenerator`. Результат собирается в `MyArrayList<Car>`.
5. После успешной загрузки меню сохраняет новую исходную коллекцию и сбрасывает предыдущий результат сортировки.
6. Пользователь выбирает алгоритм, затем способ сравнения. Меню передаёт алгоритму копию исходной коллекции и выбранный компаратор.
7. После успешной сортировки меню сохраняет результат. Его можно показать или дописать в файл.

Главное меню работает в цикле. Пункт `0` завершает программу; в подменю он возвращает назад. Неверное число повторяет текущий запрос. Конец консольного ввода передаётся в `Main` как `EOFException`: программа сообщает об ошибке ввода и завершается с кодом `1`.

Все модули подключены в `Modules`. Проверки отсутствующих реализаций сохранены для необязательных пунктов: при подстановке `null` вместо такого модуля меню сообщает о недоступности операции. Точные методы подключения перечислены в [контрактах](contracts.md#подключение).

## Модель и проверка данных

У `Car` три обязательных поля:

- `power` — положительное целое число;
- `model` — непустая строка после удаления пробелов по краям; `;` и переводы строк запрещены в исходном значении;
- `productionYear` — целое число от 1900 до текущего года включительно.

Ограничения проверяет `Car.Builder.build()`. Все источники создают автомобили через Builder. Парсер отвечает за формат строки и преобразование чисел, Builder — за допустимость значений. Ручной ввод повторяет запрос некорректного поля, файловый ввод отклоняет загрузку с плохой строкой.

### Формат файла

UTF-8, без заголовка, одна запись на строку:

```text
150;Kia;2020
100;Audi;2018
120;Лада;2022
```

Поля разделяются `;`, пробелы по краям удаляются. Полей должно быть ровно три. Пустая строка, неверное число или недопустимое значение отклоняют загрузку; сообщение содержит номер строки и причину.

`StreamFileCarSource` проверяет **весь файл**, даже если запрошено меньше записей, и возвращает первые `length` автомобилей. Ошибка после выбранных записей также отклоняет загрузку. Нехватка записей считается ошибкой. `CarFileWriter` использует тот же формат, поэтому сохранённые данные можно загрузить обратно.

## Сортировка и сохранность исходных данных

Компаратор сравнивает два объекта, алгоритм переставляет элементы коллекции. Сортировки вставками, выбором и пузырьком используют переданный `Comparator<Car>`. При сравнении по всем полям порядок фиксирован: мощность → модель → год. Следующее поле учитывается только при равенстве предыдущих. Числа сравниваются по возрастанию, модели — через `String.compareTo`, с учётом регистра. Компаратор одного поля не учитывает остальные поля.

Меню вызывает `copy()` у исходной коллекции и передаёт полученный контейнер алгоритму. Копия содержит те же ссылки на автомобили. Этого достаточно: `Car` не меняется после создания. Сортировка сохраняет размер коллекции и все повторяющиеся элементы.

Исходные данные и результат хранятся отдельно. Успешная загрузка заменяет исходную коллекцию и сбрасывает старый результат. Ошибка загрузки, отмена выбора или ошибка сортировки сохраняет прежние данные и результат. Сам алгоритм при исключении может успеть изменить переданный контейнер, поэтому меню сохраняет новую копию только после успешного завершения операции.

### Чётные мощности

`EvenValueSorter<T>` выбирает элементы с чётным значением поля, сортирует их одной из трёх стратегий и возвращает на те позиции, которые занимали чётные элементы. Объекты с нечётным значением остаются на исходных индексах. В меню используется мощность (`Car::getPower`), поэтому отдельный компаратор пользователь не выбирает. Этот режим также работает с копией и сохраняет результат в `sortedCars`.

### Подсчёт и запись

`CarCounter` получает исходную коллекцию, автомобиль-образец и число потоков. Совпадением считается равенство всех трёх полей. Рабочие потоки обрабатывают разные индексы, после их завершения результаты суммируются. Коллекция при этом не меняется. Меню выводит количество совпадений; отдельная коллекция найденных автомобилей не создаётся.

`CarFileWriter` получает результат последней обычной или чётной сортировки. Он добавляет записи в конец указанного файла, сохраняя прежнее содержимое. Ошибка записи не меняет коллекции приложения, но часть записей может уже попасть в файл. Подсчёт и запись результата сортировки выполняются независимо.

## Как расширять приложение

`SortStrategy<T>` — интерфейс алгоритмов, через который реализован паттерн Strategy: меню вызывает метод `sort`, а порядок перестановок определяет выбранная реализация. Источники аналогично подключаются через `DataSource<T>`. Сигнатуры, ошибки и ограничения описаны в [контрактах модулей](contracts.md).

`T` — тип элементов. `MyArrayList<T>`, три алгоритма и `EvenValueSorter<T>` работают с ним, не обращаясь к полям `Car`. Для другого порядка достаточно нового компаратора; для другого числового поля — функции извлечения значения. Для другой модели понадобятся свои источники и проверка данных, а универсальные части можно использовать без изменения.

`Modules` связывает контракты с конкретными реализациями. Чтобы заменить алгоритм существующего пункта, нужно вернуть реализацию того же контракта из соответствующего метода. Новая операция требует отдельного подключения в меню. Порядок совместной работы описан в [плане команды](development-plan.md), показ приложения — в [сценарии защиты](demo.md).
