# Подключение модулей — объяснение для защиты

Эта памятка дополняет [общий сценарий защиты](demo.md). Она помогает объяснить устройство `Modules` на примере записи результата в файл.

## Как устроено подключение

[`Modules`](../src/app/Modules.java) — обычный класс, в котором собраны методы создания модулей приложения. Например, он выбирает реализацию записи автомобилей:

```java
public ResultWriter<Car> carResultWriter() {
    return new CarFileWriter();
}
```

[`ConsoleApplication`](../src/app/ConsoleApplication.java) получает этот объект через `Modules`. Для работы с записью меню использует интерфейс [`ResultWriter<Car>`](../src/contract/ResultWriter.java), то есть общий контракт записи. Основные строки из `writeCars()`:

```java
ResultWriter<Car> writer = modules.carResultWriter();
```

```java
writer.append(sortedCars, path);
```

Между этими действиями меню проверяет наличие модуля, запрашивает и проверяет путь. Если `Modules` вернул `null`, меню сообщает, что запись ещё не подключена, и завершает действие до запроса пути. Метод `append` добавляет результат в конец файла, сохраняя прежние записи; при отсутствии файла создаёт его.

## Зачем это нужно

Чтобы подключить другую готовую реализацию того же контракта, достаточно изменить метод `carResultWriter()` в `Modules`. Меню продолжит вызывать прежний `append`: детали записи находятся в выбранном классе.

Например, можно представить новый `JsonCarFileWriter`, реализующий `ResultWriter<Car>`. **Такого класса в проекте нет.** Это пример возможного расширения: после его разработки `Modules` мог бы возвращать `new JsonCarFileWriter()`. JSON потребует отдельно согласовать новый формат файла и правила добавления записей. Сейчас приложение использует UTF-8 и строки `мощность;модель;год`; текущий файловый ввод JSON не поддерживает.

Та же точка подключения полезна для тестов. В `ConsoleApplication` можно передать наследника `Modules`, у которого `carResultWriter()` возвращает тестовую реализацию. Она запоминает переданные автомобили и путь, не создавая реальных файлов. Так можно проверить, что меню передало на запись нужный результат. Саму запись на диск проверяют отдельно.

## Текст для выступления на 1–2 минуты

«В нашем приложении создание модулей собрано в обычном классе `Modules`. Покажу это на записи результата. Метод `carResultWriter()` создаёт `CarFileWriter`, а меню получает его как `ResultWriter<Car>`. Это интерфейс с общим контрактом записи: метод `append` принимает коллекцию автомобилей и путь к файлу.

Меню отвечает за общение с пользователем: проверяет наличие результата и модуля записи, спрашивает путь и выводит сообщение. Создание конкретного модуля находится в `Modules`, а работа с файлом — в `CarFileWriter`.

Если понадобится другая реализация записи с тем же контрактом, мы изменим её подключение в одном методе `Modules`. Вызов `append` в меню останется прежним. Например, можно разработать `JsonCarFileWriter`. Сейчас его нет, и новый формат пришлось бы согласовать отдельно: действующий формат проекта — мощность, модель и год через точку с запятой.

Для тестов вместо обычного модуля можно подключить реализацию, которая только запоминает полученные данные. Мы проверим передачу результата из меню без создания файлов. Таким образом, `Modules` определяет, какие реализации используются, а интерфейсы позволяют меню работать с ними через общий контракт».
