# Краткий план демонстрации и обзора кода

Этот вариант помогает быстро увидеть общий план выступления: сначала показ приложения, затем краткий обзор кода. Основной [подробный сценарий защиты](demo.md) связывает объяснения с каждым действием и показывает все три алгоритма и четыре компаратора. Здесь часть этих проверок оставлена в резерве.

Это самостоятельные варианты с разным порядком действий. Для каждого нужен новый запуск приложения и новый выходной файл. В этом плане дважды сохраняем обычную сортировку шести автомобилей — получаем 12 строк. В подробном сценарии дважды сохраняем пять автомобилей после чётной сортировки — получаем 10 строк.

План рассчитан на 18 минут, ещё 2 минуты оставляем на вопросы. Экраном управляет один человек. Рассказать о проекте может один участник или несколько: переходы между докладчиками нужно заранее отрепетировать. Правила курса — в [постановке задания](requirements.md).

## Что подготовить до выступления

1. Открыть актуальную `main` как Maven-проект в IntelliJ IDEA. Проверить JDK 17 или новее и рабочую папку запуска — корень репозитория.
2. Выполнить `./mvnw clean test` (Windows: `.\mvnw.cmd clean test`). Сделать это заранее, чтобы на защите не ждать скачивания Maven и зависимостей.
3. Открыть `Main`, `Modules`, `Car`, `InsertionSort`, `CarAllFieldsComparator` и классы дополнений из таблицы ниже. Увеличить шрифт редактора и консоли.
4. Подготовить новое имя выходного файла, например `target/demo-outline-result.txt`. Если такой файл уже есть, выбрать другое имя: запись добавляет строки к существующим. Папка `target` появится после сборки.
5. Назначить демонстратора и докладчиков. Пройти сценарий с секундомером; основную часть закончить за 18 минут. Репетиция с командой — отдельный шаг после подготовки материалов.
6. Проверить запуск по README на другом компьютере. На GitHub проверить доступность ссылки, слияние рабочих веток в `main` и наличие веток с кодом по числу участников.

Все пути ниже указаны относительно корня репозитория. Стрелка в описании означает следующий ответ на запрос программы; её вводить не нужно. Для запуска можно использовать кнопку возле `Main.main` или команду `java -cp target/classes sorting.app.Main` после сборки.

## 0:00–1:00 — назначение приложения

«Мы выбрали класс `Car`: мощность, модель и год выпуска. Пользователь выбирает длину коллекции, источник данных, алгоритм и правило сравнения. Программа работает в цикле до выбора выхода. Есть три алгоритма сортировки и все дополнительные задания».

Коротко показать главное меню. Объяснить: `0` в главном меню завершает программу, в подменю возвращает в главное меню.

## 1:00–5:00 — загрузка, сортировка, подсчёт и запись

### Загрузить шесть автомобилей

В меню: `1` → `1` → `examples/cars-sort.txt` → `6`. Затем `3` — показать исходную коллекцию.

Обратить внимание на одинаковую мощность и две одинаковые записи `150;Kia;2018`: пример позволяет увидеть сравнение по всем трём полям и проверить подсчёт.

### Отсортировать по всем полям

В меню: `2` → `1` (вставками) → `1` (по всем трём полям), затем `4`.

Ожидаемый порядок записей:

```text
100;Volvo;2022
150;Audi;2022
150;Kia;2018
150;Kia;2018
150;Kia;2022
200;Audi;2010
```

Объяснить приоритет: сначала мощность, при равной мощности — модель, при одинаковой модели — год. Поэтому `Audi` с мощностью 150 идёт перед `Kia`, а у `Kia` 2018 год идёт перед 2022. Повторы не исчезают.

Нажать `3`: исходный порядок остался прежним, поскольку приложение сортирует копию коллекции. Указать, что в меню также доступны выбором и пузырьком; для сравнения по одному полю есть отдельные пункты.

### Подсчитать совпадения

В меню: `5` → мощность `150` → модель `Kia` → год `2018` → число потоков `3`.

Результат: `Найдено совпадений: 2`. Совпадением считается автомобиль с одинаковыми значениями всех трёх полей. Подсчёт работает с исходной коллекцией.

### Сохранить дважды

В меню: `6` → `target/demo-outline-result.txt`. Повторить `6` и тот же путь.

Открыть созданный файл в IDEA. При новом имени файла должно быть 12 строк: две последовательные копии результата из шести автомобилей. Это показывает режим добавления. Путь для обеих записей должен совпадать.

## 5:00–7:00 — ошибки не завершают программу

Проверки выполняются с уже загруженными шестью автомобилями и результатом сортировки.

| Что сделать | Что показать |
| --- | --- |
| В главном меню ввести `abc`, затем `99`, затем допустимую команду | После каждой ошибки программа повторяет запрос |
| `1` → `1` → `examples/cars-invalid.txt` → `1` | Ошибка во второй строке: отрицательная мощность. Файл проверяется целиком, даже если запрошена одна запись |
| `1` → `1` → `examples/cars-sort.txt` → `7` | Сообщение о нехватке: требуется 7, найдено 6 |
| После этих ошибок выбрать `3`, затем `4` | Прежняя исходная коллекция и прежний результат сортировки сохранились |

Объяснение: новые данные заменяют старые только после успешной загрузки. Поэтому неудачная попытка загрузить файл не теряет текущую работу.

## 7:00–9:00 — ручной ввод и генератор

Выбрать `1` → `2` → длина `2`. Поля запрашиваются в порядке: мощность, модель, год.

Для первого автомобиля ввести:

- мощность: `-1`, затем исправить на `150`;
- модель: пустая строка, затем `Kia`;
- год: `1800`, затем `2020`.

После каждого неправильного значения программа должна повторить запрос этого поля. Второй автомобиль: `100`, `Лада`, `2018`.

Выбрать `3`: должны быть ровно две введённые записи. Пункт `4` сообщит, что результата сортировки пока нет: успешная загрузка новой коллекции сбрасывает прежний результат.

Затем `1` → `3` → длина `3`, после загрузки — `3`. Генератор должен создать три корректных автомобиля. Конкретные значения заранее не фиксированы.

## 9:00–11:00 — сортировка только чётных значений

Загрузить: `1` → `1` → `examples/cars-even.txt` → `5`. Нажать `3`.

Исходные мощности: `180, 151, 100, 131, 140`.

Выбрать `7` → `3` (пузырьком), затем `4`.

```text
100;Kia;2022
151;Лада;2019
140;Audi;2018
131;Toyota;2021
180;Volvo;2020
```

Объяснить: проверяется чётность мощности, а не номера позиции. Автомобили с мощностью 151 и 131 остаются на втором и четвёртом местах. Остальные автомобили целиком меняются местами; их поля не переписываются. Для этого режима доступны все три алгоритма. Пункт `3` снова показывает исходный порядок.

Завершить программу через `0`.

Не читать классы целиком. Открыть нужный метод и объяснить его ответственность. На каждый пункт — около минуты.

## Если спросят о решениях

- **Почему один `Car`, а не любые классы из меню?** По условию нужно выбрать один класс. Сами алгоритмы обобщены через `<T>` и принимают компаратор; ввод и пункты меню настроены на автомобили.
- **Где Strategy?** В контракте `SortStrategy<T>` и его трёх реализациях. Компаратор определяет, что считать больше или меньше, а стратегия — как переставлять элементы.
- **Почему такой приоритет полей?** Условие требует сравнения по всем трём полям, но не задаёт их приоритет. В проекте зафиксирован порядок: мощность → модель → год.
- **Зачем собственная коллекция?** Это дополнительное задание 3*. `MyArrayList` хранит элементы в расширяемом массиве и предоставляет операции, нужные модулям.
- **Stream — это многопоточность?** Не обязательно. Заполнение здесь последовательное. Многопоточный подсчёт реализован отдельно через `Thread`; Stream сам по себе не означает запуск рабочих потоков.
- **Есть ли готовая сортировка?** Алгоритмы написаны вручную. Компаратор сравнивает два объекта, но сам коллекцию не сортирует.
- **Что записывается в файл?** Последний результат обычной или чётной сортировки. Подсчёт выводит количество совпадений в консоль.

## Запасные проверки для вопросов и репетиции

- Загрузить файл, повторить обычную сортировку алгоритмами 2 и 3 с тем же компаратором: результат должен совпасть с сортировкой вставками.
- Выбрать сравнение только по модели или году. При равных значениях выбранного поля не обещать дополнительного порядка по остальным полям.
- Повторить режим `7` алгоритмами 1 и 2: мощности должны быть `100, 151, 140, 131, 180`.
- Попытаться сохранить до первой сортировки: приложение сообщает об отсутствии результата.
- При готовом результате указать для записи путь к каталогу, например `target`: приложение сообщает об ошибке записи, результат остаётся доступен через `4`.
- Выбрать `0` в подменю алгоритма: приложение вернётся в главное меню и сохранит предыдущий результат.
