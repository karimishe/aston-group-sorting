# Контракты модулей

Здесь зафиксированы методы и правила, на которые опираются остальные части приложения. Интерфейсы находятся в `sorting.contract`. Сейчас реализованы `FileCarSource` и `InsertionSort<T>`; остальные модули описаны в [плане разработки](development-plan.md).

Все ссылочные параметры интерфейсов обязательны: реализации должны отклонять `null` с `NullPointerException`. Исключения передаются вызывающему коду, а не заменяются пустым или частичным результатом. Изменения общих интерфейсов нужно согласовывать с командой.

## Коллекция

`MyArrayList<T>` используется всеми модулями. Она хранит элементы без `null` и увеличивает внутренний массив по мере заполнения.

| Метод | Поведение |
| --- | --- |
| `add(item)` | Добавляет элемент в конец |
| `get(index)` | Возвращает элемент по индексу |
| `set(index, item)` | Заменяет элемент без изменения размера |
| `size()`, `isEmpty()` | Возвращают размер и признак пустой коллекции |
| `copy()` | Создаёт отдельный контейнер с теми же ссылками на элементы |

Индексы начинаются с нуля. Неверный индекс в `get` или `set` вызывает `IndexOutOfBoundsException`; `null` в `add` или `set` — `NullPointerException`. Изменение копии не меняет исходный контейнер, но сами объекты не копируются. `Car` неизменяемый, поэтому может храниться в обоих контейнерах.

Коллекция не рассчитана на одновременную запись из нескольких потоков. Во время параллельного подсчёта её нельзя менять; при заполнении через Stream используется последовательная обработка.

## Источник данных — `DataSource<T>`

```java
MyArrayList<T> load(int length) throws IOException;
```

Возвращает новую коллекцию ровно из `length` проверенных элементов. Неположительная длина вызывает `IllegalArgumentException`, ошибка чтения — `IOException`. Путь, читатель консоли и другие настройки передаются источнику при создании.

`FileCarSource` получает `Path` через конструктор. Читает UTF-8, проверяет весь файл и возвращает первые `length` автомобилей. Плохая строка или нехватка записей вызывают `IllegalArgumentException`; ошибка чтения, в том числе неверная кодировка, — `IOException`. Формат описан в [архитектуре](architecture.md#формат-файла).

Готовый `CarLineParser.parse(line)` возвращает один автомобиль через Builder: неверные формат или значения вызывают `IllegalArgumentException`, `null` — `NullPointerException`. Номер строки к ошибке добавляет файловый источник. Общий `ConsoleInput` предоставляет `readLine(prompt)` и `readInt(prompt, min, max)`; оба передают ошибки чтения через `IOException`, конец ввода — через `EOFException`.

`CarConsoleReader` и `CarGenerator` будут добавлены вместе с ручным и случайным источниками. Затем их, как и `CarLineParser`, используют версии источников через Stream с тем же интерфейсом `DataSource<T>`. Создание или разбор объектов должны происходить внутри Stream; обернуть готовую коллекцию недостаточно. Готовая сортировка `Stream.sorted()` запрещена условием.

## Алгоритм — `SortStrategy<T>`

```java
void sort(MyArrayList<T> items, Comparator<T> comparator);
```

Меняет порядок элементов в переданном контейнере. Размер, ссылки на объекты и число повторений сохраняются. Пустая коллекция и один элемент допустимы; оба аргумента обязательны и для пустой коллекции. Сохранение относительного порядка равных элементов не требуется. При исключении контейнер может остаться частично изменённым: откат не входит в обязанности алгоритма. Меню сортирует копию и сохраняет её только после успеха.

Алгоритм сравнивает элементы только через переданный компаратор. `CarAllFieldsComparator` использует порядок мощность → модель → год: числа по возрастанию, строки через `String.compareTo`, с учётом регистра. Следующее поле учитывается при равенстве предыдущих. `null` вызывает `NullPointerException`; результат `0` означает совпадение всех трёх полей, даже у разных объектов. Отдельные `CarPowerComparator`, `CarModelComparator` и `CarProductionYearComparator` ещё предстоит добавить.

## Чётные значения — `EvenSorter<T>`

```java
void sort(MyArrayList<T> items, ToIntFunction<T> field, SortStrategy<T> strategy);
```

`field` извлекает целое число из объекта; для автомобиля используем мощность. Модуль выбирает объекты с чётным значением, сортирует их переданной стратегией по возрастанию этого значения и возвращает на те же позиции. Объекты с нечётным значением остаются на исходных индексах. Чётность относится к значению поля, а не к индексу. Пустая коллекция допустима. Реализацию нужно проверить со всеми подключёнными алгоритмами.

## Запись — `ResultWriter<T>`

```java
void append(MyArrayList<T> items, Path path) throws IOException;
```

Добавляет записи в конец файла, создаёт файл при его отсутствии и не меняет коллекцию. Ошибки записи передаются через `IOException`. Будущий `CarFileWriter` использует UTF-8 и формат `мощность;модель;год`, одна запись на строку. Если прежний файл не заканчивается переводом строки, новая запись должна начинаться с новой строки.

## Подсчёт — `OccurrenceCounter<T>`

```java
int count(MyArrayList<T> items, T target, int threadCount) throws InterruptedException;
```

Считает совпадения с `target` через `equals`, не изменяя коллекцию. Использует не больше `threadCount` рабочих потоков, каждый обрабатывает свой непересекающийся диапазон. Пустая коллекция даёт `0`. Число потоков должно быть положительным даже для неё, иначе — `IllegalArgumentException`.

При прерывании нужно завершить запущенные рабочие потоки и передать `InterruptedException`; частичный результат нельзя выдавать за полный. Подсчёт не требует сортировки. Метод возвращает число, меню выводит его в консоль.

В проекте `N` из задания трактуется как автомобиль-образец. Совпадением считаем равенство всех трёх полей. У `Car` пока нет собственных `equals` и `hashCode`: тимлид добавит их перед подключением подсчёта. До этого универсальный счётчик можно проверять на `Integer` или `String`, затем добавить тест с разными объектами `Car`, у которых совпадают поля.

## Подключение

Участник реализует интерфейс в отдельном классе и добавляет тесты. Тимлид подключает готовый класс в `Modules` и меню; общие модель, коллекция и интерфейсы для этого не меняются. Пока неготовые пункты меню только выводят сообщение и возвращают пользователя назад. Текущая схема вызовов описана в [архитектуре](architecture.md), состав рабочей версии — в [каркасе](scaffold.md).
