# Контракты модулей

Здесь зафиксированы методы и правила взаимодействия модулей. Общие интерфейсы находятся в `sorting.contract`. Реализации подключаются через `Modules`; меню обращается к ним через эти интерфейсы.

Ссылочные параметры должны быть ненулевыми. Конкретные виды исключений описаны ниже: например, сортировки отклоняют `null` через `NullPointerException`, а `CarCounter` — через `IllegalArgumentException`. Ошибка операции передаётся вызывающему коду, а не заменяется успешным частичным результатом. Изменения общих интерфейсов согласуем с командой.

## Коллекция

`MyArrayList<T>` используется всеми модулями. Она хранит элементы без `null` и увеличивает внутренний массив по мере заполнения.

| Метод | Поведение |
| --- | --- |
| `add(item)` | Добавляет элемент в конец |
| `addAll(items)` | Добавляет элементы другой коллекции в их порядке; при добавлении коллекции в себя повторяет исходные элементы один раз |
| `get(index)` | Возвращает элемент по индексу |
| `set(index, item)` | Заменяет элемент без изменения размера |
| `size()`, `isEmpty()` | Возвращают размер и признак пустой коллекции |
| `copy()` | Создаёт отдельный контейнер с теми же ссылками на элементы |

Индексы начинаются с нуля. Неверный индекс в `get` или `set` вызывает `IndexOutOfBoundsException`; `null` в `add`, `addAll` или `set` — `NullPointerException`. В `set` индекс проверяется первым. Изменение копии не меняет исходный контейнер, но сами объекты не копируются. Неизменяемый `Car` может храниться в обоих контейнерах.

Коллекция не рассчитана на одновременную запись из нескольких потоков. Во время многопоточного подсчёта её нельзя менять. Источники заполняют её последовательными Stream.

## Источник данных — `DataSource<T>`

```java
MyArrayList<T> load(int length) throws IOException;
```

Возвращает новую коллекцию ровно из `length` допустимых элементов. Неположительная длина вызывает `IllegalArgumentException`, ошибка чтения — `IOException`. Конструкторы сохраняют настройки, но не читают данные и не показывают запросы: это делает `load`. Количество элементов запрашивает меню.

| Подключённая реализация | Настройки и поведение |
| --- | --- |
| `StreamFileCarSource` | Получает `Path`; читает UTF-8, проверяет весь файл и возвращает первые `length` автомобилей |
| `StreamManualCarSource` | Получает общий `ConsoleInput`; через `CarConsoleReader` запрашивает `length` автомобилей |
| `StreamRandomCarSource` | Через `CarGenerator` создаёт `length` допустимых автомобилей; повторяющиеся значения разрешены |

Все три источника создают или разбирают автомобили внутри Stream и собирают результат в `MyArrayList<Car>`. Конструкторы отклоняют `null` вместо пути, общего ввода или переданного генератора через `NullPointerException`.

У файлового источника плохая строка или нехватка записей вызывают `IllegalArgumentException`; отсутствие файла, неверная кодировка и другие ошибки чтения — `IOException`. Проверяются и строки после запрошенного количества. Частичная коллекция не возвращается. [Формат файла](architecture.md#формат-файла) общий для чтения и записи.

`CarLineParser.parse(line)` возвращает автомобиль через Builder: неверные формат или значения вызывают `IllegalArgumentException`, `null` — `NullPointerException`. Номер строки к ошибке добавляет файловый источник.

`CarConsoleReader` использует общий `ConsoleInput`: мощность и год читаются через `readInt`, модель — через `readLine`. Неверное число, пустая модель или модель с `;` запрашиваются повторно. Ручной источник не закрывает общий читатель. Ошибки чтения передаются как `IOException`, конец ввода — как исходный `EOFException`, который доходит до `Main`.

В `ConsoleInput.readInt(prompt, min, max)` границы включены. При `min > max` возникает `IllegalArgumentException` до чтения строки. `readLine` сохраняет пробелы и пустые строки; их обработка зависит от вызывающего модуля.

## Алгоритм — `SortStrategy<T>`

```java
void sort(MyArrayList<T> items, Comparator<T> comparator);
```

`InsertionSort<T>`, `SelectionSort<T>` и `BubbleSort<T>` меняют порядок элементов в переданном контейнере. Размер, ссылки на объекты и число повторений сохраняются. Пустая коллекция и один элемент допустимы; `null` вместо любого аргумента вызывает `NullPointerException` даже для пустой коллекции. Сохранение относительного порядка равных элементов не входит в общий контракт.

Алгоритм сравнивает элементы только через переданный компаратор. При исключении контейнер может остаться частично изменённым: откат не входит в обязанности алгоритма. Меню сортирует копию и сохраняет её только после успеха.

| Компаратор | Порядок сравнения |
| --- | --- |
| `CarAllFieldsComparator` | Мощность → модель → год; следующее поле учитывается при равенстве предыдущих |
| `CarPowerComparator` | Мощность по возрастанию |
| `CarModelComparator` | Модель через `String.compareTo`, с учётом регистра |
| `CarProductionYearComparator` | Год по возрастанию |

Все компараторы отклоняют `null` через `NullPointerException`. Результат `0` означает равенство сравниваемых полей, даже у разных объектов. Компараторы одного поля не сравнивают остальные поля.

## Чётные значения — `EvenSorter<T>`

```java
void sort(MyArrayList<T> items, ToIntFunction<T> field, SortStrategy<T> strategy);
```

`field` извлекает целое число из объекта. `EvenValueSorter<T>` сортирует элементы с чётными значениями по возрастанию этого поля с помощью переданной стратегии. Объекты с нечётными значениями остаются на исходных индексах. Чётность относится к значению поля, а не к индексу.

Размер коллекции, элементы и повторы сохраняются. Пустая коллекция допустима; `null` вместо любого аргумента вызывает `NullPointerException`. В приложении используется `Car::getPower`, доступны все три алгоритма. Меню передаёт копию исходной коллекции и сохраняет её как результат только после успеха.

## Запись — `ResultWriter<T>`

```java
void append(MyArrayList<T> items, Path path) throws IOException;
```

`CarFileWriter` добавляет автомобили в конец файла и не меняет коллекцию. Коллекция и путь должны быть ненулевыми. Используются UTF-8 и формат `мощность;модель;год`, одна запись на строку.

- Файл создаётся, если его нет; родительская папка должна существовать.
- Если непустой файл не заканчивается символом `\n`, перед добавлением записей дописывается системный перевод строки.
- Пустая коллекция не добавляет автомобили, но создание файла и добавление разделителя при необходимости всё равно выполняются.
- Повторный вызов добавляет те же записи повторно; проверки уникальности нет.
- Ошибка создания, чтения конца файла или записи передаётся через `IOException`.

Запись выполняется последовательно и не откатывается: при ошибке часть данных может уже оказаться в файле. Меню передаёт результат последней сортировки и сообщает об успешном сохранении после завершения `append`.

## Подсчёт — `OccurrenceCounter<T>`

```java
int count(MyArrayList<T> items, T target, int threadCount) throws InterruptedException;
```

`CarCounter` считает совпадения с `target`, не изменяя коллекцию. Для автомобилей совпадение означает равенство мощности, модели и года, даже у разных объектов. Подсчёт не требует предварительной сортировки.

Реализация создаёт `threadCount` рабочих потоков и распределяет между ними индексы коллекции. Число потоков может превышать число элементов. Пустая коллекция даёт `0`. Неположительное число потоков, `null` вместо коллекции или образца вызывают `IllegalArgumentException`. Меню ограничивает число потоков диапазоном от `1` до `255`.

При прерывании вызывающего потока до начала работы метод выбрасывает `InterruptedException`. Если прерывание происходит при ожидании результата, реализация прерывает запущенные рабочие потоки, дожидается их завершения и передаёт `InterruptedException`; частичный результат не возвращается.

Метод возвращает количество, меню выводит его в консоль. Результат подсчёта не сохраняется отдельной коллекцией и не передаётся в `CarFileWriter`.

## Подключение

`Modules` создаёт конкретные реализации. Все перечисленные методы возвращают подключённые модули:

| Метод `Modules` | Реализация |
| --- | --- |
| `fileSource(Path path)` | `StreamFileCarSource` |
| `manualSource(ConsoleInput input)` | `StreamManualCarSource` с общим читателем |
| `randomSource()` | `StreamRandomCarSource` |
| `sortStrategy()` | `InsertionSort<Car>` |
| `selectionSort()` | `SelectionSort<Car>` |
| `bubbleSort()` | `BubbleSort<Car>` |
| `carComparator()` | `CarAllFieldsComparator` |
| `powerComparator()` | `CarPowerComparator` |
| `modelComparator()` | `CarModelComparator` |
| `productionYearComparator()` | `CarProductionYearComparator` |
| `evenSorter()` | `EvenValueSorter<Car>` |
| `carResultWriter()` | `CarFileWriter` |
| `carCounter()` | `CarCounter` |

Для замены реализации существующего пункта достаточно вернуть объект того же контракта из соответствующего метода. Для проверки взаимодействия можно передать в `ConsoleApplication` наследника `Modules` с тестовыми реализациями.

Защитные проверки `null` сохранены для необязательных источников, алгоритмов, компараторов, чётной сортировки и записи. Они позволяют сообщить о недоступной операции при подмене модуля. Новые операции и изменения общих контрактов согласуем с командой.
